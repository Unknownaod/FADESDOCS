Fades Identity · OAuth 2.0 + OpenID Connect
Fades Identity · v1

Sign users in with Fades.

Fades Identity is an OAuth 2.0 and OpenID Connect provider. Add “Sign in with Fades” to your app using the Authorization Code flow with PKCE, then read the user’s profile and email with a single API call.

Getting started

Quickstart

From zero to a signed-in user in about five steps.

  1. Register your app. Create an app to get a client_id (and a client_secret if it’s a server-side app). Add your callback URL as a redirect URI. See Registering an app.
  2. Send the user to Fades. Generate a PKCE verifier and challenge, then redirect the browser to /oauth/authorize.
  3. Receive the code. After the user approves, Fades redirects back to your redirect URI with ?code=…&state=…. The code works once and expires in 60 seconds.
  4. Exchange the code. POST the code and your PKCE verifier to /oauth/token from your server. You get an access token, a refresh token and an ID token.
  5. Load the profile. Call /oauth/userinfo with the access token, or verify the ID token.

The shortest working version using the JavaScript client:

import { FadesIdentity, createPkcePair, randomString } from "./fades-identity.js";

const fades = new FadesIdentity({
  clientId: "fades_YOUR_CLIENT_ID",
  clientSecret: process.env.FADES_CLIENT_SECRET, // server only. Omit for public apps
  redirectUri: "https://example.com/auth/callback",
});

// 1. Start sign-in
const { verifier, challenge } = await createPkcePair();
const state = randomString(16);
// ...save verifier + state (session or cookie), then redirect to:
const url = fades.authorizationUrl({ challenge, state });

// 2. In your callback route
const tokens = await fades.exchangeCode({ code, verifier });
const user = await fades.userinfo(tokens.access_token);
console.log(user.preferred_username, user.email);
Getting started

Core concepts

Apps (clients)

An app is how Fades knows who is asking. Each app has a client_id that starts with fades_ and a list of exact-match redirect URIs.

TypeHas a secret?Use it for
ConfidentialYes. Shown once at creationServer-side apps: Next.js API routes, Express, Python backends. The secret never leaves your server.
PublicNo. Relies on PKCESingle-page apps, desktop apps and mobile apps that can’t keep a secret.

Scopes

Scopes decide what ends up in the ID token and UserInfo response. If you omit scope, it defaults to openid.

ScopeGrantsClaims returned
openidRequired for sign-in. Enables the ID token and UserInfosub
profileUsername, display name, avatarname, preferred_username, picture
emailEmail address and verification statusemail, email_verified

PKCE

PKCE (Proof Key for Code Exchange) ties the authorization code to the app instance that asked for it, so a stolen code is useless. You create a random code verifier, send its SHA-256 hash (the code challenge) when you start sign-in, and send the verifier itself when you redeem the code.

  • Verifier: 43–128 characters from A–Z a–z 0–9 - . _ ~. Generate 32 random bytes and base64url-encode them.
  • Challenge: base64url(SHA-256(verifier)), without = padding. Always send code_challenge_method=S256. plain is not supported.
Guides

Authorization flow

The Authorization Code flow with PKCE, step by step.

  1. Your app creates verifier, challenge, state (and optionally nonce) and stores them where the callback can find them.
  2. Browser → Fades GET /oauth/authorize?… Fades validates the app and redirect URI, then forwards the user to auth.fades.lol.
  3. User signs in and approves or denies the requested scopes.
  4. Fades → your callback The browser lands on your redirect URI with code and state (or error and state).
  5. Your server → Fades POST /oauth/token with the code, redirect URI and code_verifier.
  6. Fades → your server returns access_token, refresh_token and, for openid, an id_token.
  7. Your server → Fades GET /oauth/userinfo with the access token to load the profile.
Always check state. Compare the state on the callback with the one you saved. If it doesn’t match, stop. That request wasn’t started by your app.
The redirect URI must match exactly. The redirect_uri you send to /authorize and /token must be identical, character for character, to one registered on the app, including trailing slashes.
Guides

Registering an app

Create an app with POST /oauth/clients while signed in to Fades (the dashboard does this for you). The response contains the clientId and, for confidential apps, the clientSecret.

The client secret is shown once. Fades stores only a hash of it. If you lose it, delete the app and create a new one.

Redirect URI rules

  • 1 to 10 redirect URIs per app, each an absolute URL.
  • https:// is required. http:// is allowed only for localhost and 127.0.0.1 (for development).
  • No URL fragments (#…) and no credentials in the URL (user:pass@).
  • You can have up to 20 apps per account. App names are trimmed to 60 characters.

Which type should I pick?

  • Do you have a backend that can keep an environment variable private? Create a confidential app and do the token exchange there.
  • Pure front-end or native app? Create a public app ("public": true). PKCE protects the exchange.
Guides

ID tokens

When you request the openid scope, the token response includes an id_token: a JWT signed with RS256. It proves who signed in. Use it right after the exchange to establish your own session. It lives for only 5 minutes.

Header

{ "alg": "RS256", "typ": "JWT", "kid": "fades-rsa-1" }

Claims

ClaimAlways?Description
issYesIssuer: https://api.fades.lol
subYesThe user’s stable, unique ID. Use this as your user key
audYesYour client_id
iat, expYesIssued-at and expiry, in Unix seconds
nonceIf you sent oneThe nonce from your authorize request
nameprofileDisplay name (falls back to the username)
preferred_usernameprofileThe user’s Fades username
pictureprofile, if setAvatar URL
emailemail, if setEmail address
email_verifiedemailtrue or false

Verifying it

Fetch the public key from the JWKS endpoint, check the RS256 signature, then check iss, aud, exp and nonce. A ready-made example is in Verify an ID token. If you only need the profile, the UserInfo endpoint is simpler.

Refreshing a token (grant_type=refresh_token) does not return a new ID token. Use UserInfo for fresh profile data.
Guides

Tokens & refresh

TokenLifetimeNotes
Authorization code60 secondsSingle use. Consumed the moment you redeem it
Access token1 hour (expires_in: 3600)Opaque string. Send as Authorization: Bearer …
Refresh token30 daysOpaque. Rotates: every refresh returns a new one and kills the old one
ID token5 minutesRS256 JWT. For establishing a session, not for API calls

Rotation in practice

Each time you call the token endpoint with grant_type=refresh_token, Fades issues a new access token and a new refresh token, and the one you used stops working. Always save the new refresh token. If two requests race with the same refresh token, one wins and the other gets invalid_grant.

Signing users out

Call POST /oauth/revoke with the access or refresh token. Users can also disconnect your app themselves from their account (see Disconnect app), which invalidates all your tokens for that user.

GET/oauth/authorize

Authorize

Starts sign-in. Send the user’s browser here (a redirect or link, not a fetch). Fades validates the request and forwards the user to the sign-in and consent page. When they decide, they’re sent back to your redirect URI.

Browser redirectNo authentication header

Query parameters

NameDescription
client_idrequiredYour app’s ID, for example fades_a1B2c3D4e5F6g7H8
redirect_urirequiredOne of the redirect URIs registered on the app. Exact match
response_typerequiredMust be code

Errors

A missing, unknown or expired token, a token without the openid scope, or a deleted user all return 401 {"error":"invalid_token"} with a WWW-Authenticate: Bearer error="invalid_token" header. Refresh the access token and retry once.

Internal
POST/oauth/authorize/info POST/oauth/authorize/decision

Consent endpoints

These two endpoints power the Fades consent page at auth.fades.lol. Your app doesn’t call them. They’re documented so you know what the user’s approval step does.

Signed-in Fades sessiondecision: 30 requests / 10 min
  • /authorize/info takes the same fields as /authorize and returns the app name, requested scopes and the signed-in user, so the page can render “App wants access to…”.
  • /authorize/decision takes the same fields plus approve: true | false. On approval it creates a one-time code (valid 60 seconds) and returns { "success": true, "redirectTo": "…?code=…&state=…" }. On denial it returns a redirectTo with error=access_denied.
SDKs & examples

JavaScript client

A zero-dependency client for browsers and Node 19+. Copy it into your project as fades-identity.js. It isn’t published to npm, so there’s nothing to install.

// fades-identity.js: zero-dependency client for Fades Identity.
// Works in browsers and Node 19+ (needs fetch + Web Crypto).

const b64url = (bytes) =>
  btoa(String.fromCharCode(...new Uint8Array(bytes)))
    .replace(/\+/g, "-")
    .replace(/\//g, "_")
    .replace(/=+$/, "");

/** Random URL-safe string. 32 bytes gives 43 characters. */
export function randomString(bytes = 32) {
  return b64url(crypto.getRandomValues(new Uint8Array(bytes)));
}

/** Creates a PKCE verifier and its S256 challenge. */
export async function createPkcePair() {
  const verifier = randomString(32);
  const digest = await crypto.subtle.digest(
    "SHA-256",
    new TextEncoder().encode(verifier)
  );
  return { verifier, challenge: b64url(digest) };
}

export class FadesError extends Error {
  constructor(status, body) {
    super(body.error_description || body.error || "Request failed");
    this.name = "FadesError";
    this.status = status;          // HTTP status
    this.error = body.error;       // e.g. "invalid_grant"
    this.requestId = body.request_id || null; // present on server_error
  }
}

export class FadesIdentity {
  constructor({ clientId, clientSecret, redirectUri, issuer = "https://api.fades.lol" }) {
    this.clientId = clientId;
    this.clientSecret = clientSecret; // leave undefined for public apps
    this.redirectUri = redirectUri;
    this.base = issuer.replace(/\/+$/, "") + "/oauth";
  }

  /** Build the URL to send the user's browser to. */
  authorizationUrl({ challenge, state, nonce, scope = "openid profile email" }) {
    const params = Object.entries({
      client_id: this.clientId,
      redirect_uri: this.redirectUri,
      response_type: "code",
      scope,
      state,
      nonce,
      code_challenge: challenge,
      code_challenge_method: "S256",
    }).filter(([, value]) => value);

    return `${this.base}/authorize?${new URLSearchParams(params)}`;
  }

  async #post(path, body) {
    const res = await fetch(this.base + path, {
      method: "POST",
      headers: { "Content-Type": "application/json", Accept: "application/json" },
      body: JSON.stringify({
        client_id: this.clientId,
        ...(this.clientSecret ? { client_secret: this.clientSecret } : {}),
        ...body,
      }),
    });
    const data = await res.json().catch(() => ({}));
    if (!res.ok) throw new FadesError(res.status, data);
    return data;
  }

  /** Trade the callback code for tokens. */
  exchangeCode({ code, verifier }) {
    return this.#post("/token", {
      grant_type: "authorization_code",
      code,
      redirect_uri: this.redirectUri,
      code_verifier: verifier,
    });
  }

  /** Get new tokens. Save the NEW refresh token. The old one is dead. */
  refresh(refreshToken) {
    return this.#post("/token", {
      grant_type: "refresh_token",
      refresh_token: refreshToken,
    });
  }

  /** Revoke an access or refresh token (sign out). */
  revoke(token) {
    return this.#post("/revoke", { token });
  }

  /** Load the user's profile. */
  async userinfo(accessToken) {
    const res = await fetch(this.base + "/userinfo", {
      headers: { Authorization: `Bearer ${accessToken}` },
    });
    const data = await res.json().catch(() => ({}));
    if (!res.ok) throw new FadesError(res.status, data);
    return data;
  }
}

App Router route

export const dynamic = "force-dynamic";

const ISSUER = (process.env.FADES_ISSUER || "https://api.fades.lol").replace(/\/+$/, "");

export async function POST(request) {
  const clientId = process.env.FADES_CLIENT_ID;
  const clientSecret = process.env.FADES_CLIENT_SECRET;
  const redirectUri = process.env.FADES_REDIRECT_URI;

  if (!clientId || !clientSecret || !redirectUri) {
    return Response.json({ error: "server_configuration_error" }, { status: 500 });
  }

  const { code, code_verifier } = await request.json().catch(() => ({}));
  if (typeof code !== "string" || typeof code_verifier !== "string") {
    return Response.json({ error: "invalid_request" }, { status: 400 });
  }

  try {
    const upstream = await fetch(`${ISSUER}/oauth/token`, {
      method: "POST",
      headers: { "Content-Type": "application/json", Accept: "application/json" },
      cache: "no-store",
      signal: AbortSignal.timeout(20000),
      body: JSON.stringify({
        grant_type: "authorization_code",
        client_id: clientId,
        client_secret: clientSecret,
        code,
        redirect_uri: redirectUri,
        code_verifier,
      }),
    });

    // Pass Fades's status and body straight through.
    const data = await upstream.json().catch(() => null);
    if (!data) return Response.json({ error: "invalid_upstream_response" }, { status: 502 });

    return Response.json(data, {
      status: upstream.status,
      headers: { "Cache-Control": "no-store" },
    });
  } catch {
    return Response.json({ error: "upstream_unavailable" }, { status: 502 });
  }
}

Express

A complete server-side login using the JavaScript client and session storage. Install the one extra dependency with npm i express express-session.

import express from "express";
import session from "express-session";
import { FadesIdentity, createPkcePair, randomString } from "./fades-identity.js";

const app = express();

app.use(session({
  secret: process.env.SESSION_SECRET,
  resave: false,
  saveUninitialized: false,
  cookie: { httpOnly: true, sameSite: "lax", secure: process.env.NODE_ENV === "production" },
}));

const fades = new FadesIdentity({
  clientId: process.env.FADES_CLIENT_ID,
  clientSecret: process.env.FADES_CLIENT_SECRET,
  redirectUri: "https://example.com/auth/callback",
});

// Step 1: send the user to Fades
app.get("/auth/login", async (req, res) => {
  const { verifier, challenge } = await createPkcePair();
  const state = randomString(16);
  const nonce = randomString(16);

  req.session.fades = { verifier, state, nonce };
  res.redirect(fades.authorizationUrl({ challenge, state, nonce }));
});

// Step 2: Fades sends them back here
app.get("/auth/callback", async (req, res) => {
  const saved = req.session.fades;
  delete req.session.fades;

  if (req.query.error) return res.status(400).send(`Sign-in failed: ${req.query.error}`);
  if (!saved || req.query.state !== saved.state) return res.status(400).send("Invalid state");

  try {
    const tokens = await fades.exchangeCode({ code: req.query.code, verifier: saved.verifier });
    const user = await fades.userinfo(tokens.access_token);

    req.session.user = { id: user.sub, username: user.preferred_username, email: user.email };
    req.session.refreshToken = tokens.refresh_token;
    res.redirect("/");
  } catch (error) {
    console.error("fades sign-in failed", error.status, error.error, error.requestId);
    res.status(502).send("Sign-in failed. Please try again.");
  }
});

// Sign out: also revoke at Fades
app.post("/auth/logout", async (req, res) => {
  const token = req.session.refreshToken;
  if (token) await fades.revoke(token).catch(() => {});
  req.session.destroy(() => res.redirect("/"));
});

app.listen(3000);

Python

A small module with the same surface as the JavaScript client. Needs requests (pip install requests).

"""fades_identity.py: minimal client for Fades Identity."""
import base64
import hashlib
import secrets
from urllib.parse import urlencode

import requests

ISSUER = "https://api.fades.lol"


class FadesError(Exception):
    def __init__(self, status, body):
        super().__init__(body.get("error_description") or body.get("error") or "Request failed")
        self.status = status
        self.error = body.get("error")
        self.request_id = body.get("request_id")


def random_string(n=32):
    return secrets.token_urlsafe(n)


def create_pkce_pair():
    verifier = secrets.token_urlsafe(32)  # 43 characters
    digest = hashlib.sha256(verifier.encode("ascii")).digest()
    challenge = base64.urlsafe_b64encode(digest).rstrip(b"=").decode("ascii")
    return verifier, challenge


class FadesIdentity:
    def __init__(self, client_id, redirect_uri, client_secret=None, issuer=ISSUER):
        self.client_id = client_id
        self.client_secret = client_secret
        self.redirect_uri = redirect_uri
        self.base = issuer.rstrip("/") + "/oauth"

    def authorization_url(self, challenge, state, nonce=None, scope="openid profile email"):
        params = {
            "client_id": self.client_id,
            "redirect_uri": self.redirect_uri,
            "response_type": "code",
            "scope": scope,
            "state": state,
            "code_challenge": challenge,
            "code_challenge_method": "S256",
        }
        if nonce:
            params["nonce"] = nonce
        return f"{self.base}/authorize?{urlencode(params)}"

    def _post(self, path, body):
        payload = {"client_id": self.client_id, **body}
        if self.client_secret:
            payload["client_secret"] = self.client_secret
        res = requests.post(self.base + path, json=payload, timeout=20)
        data = res.json() if res.content else {}
        if not res.ok:
            raise FadesError(res.status_code, data)
        return data

    def exchange_code(self, code, verifier):
        return self._post("/token", {
            "grant_type": "authorization_code",
            "code": code,
            "redirect_uri": self.redirect_uri,
            "code_verifier": verifier,
        })

    def refresh(self, refresh_token):
        return self._post("/token", {"grant_type": "refresh_token", "refresh_token": refresh_token})

    def revoke(self, token):
        return self._post("/revoke", {"token": token})

    def userinfo(self, access_token):
        res = requests.get(
            self.base + "/userinfo",
            headers={"Authorization": f"Bearer {access_token}"},
            timeout=20,
        )
        data = res.json() if res.content else {}
        if not res.ok:
            raise FadesError(res.status_code, data)
        return data

import os
from flask import Flask, redirect, request, session
from fades_identity import FadesIdentity, FadesError, create_pkce_pair, random_string

app = Flask(__name__)
app.secret_key = os.environ["SESSION_SECRET"]

)

@app.get("/auth/login")
def login():
    verifier, challenge = create_pkce_pair()
    session["fades"] = {"verifier": verifier, "state": random_string(16)}
    return redirect(fades.authorization_url(challenge, session["fades"]["state"]))

@app.get("/auth/callback")
def callback():
    saved = session.pop("fades", None)
    if request.args.get("error") or not saved or request.args.get("state") != saved["state"]:
        return "Sign-in failed", 400
    try:
        tokens = fades.exchange_code(request.args["code"], saved["verifier"])
        user = fades.userinfo(tokens["access_token"])
    except FadesError as e:
        app.logger.error("fades error %s %s %s", e.status, e.error, e.request_id)
        return "Sign-in failed", 502
    session["user"] = {"id": user["sub"], "username": user["preferred_username"]}
    return redirect("/")

Verify an ID token

Do this whenever you rely on the ID token directly. Check the signature against the JWKS, then the issuer, audience, expiry and nonce.

import { createRemoteJWKSet, jwtVerify } from "jose"; // npm i jose

const JWKS = createRemoteJWKSet(new URL("https://api.fades.lol/oauth/jwks"));

export async function verifyIdToken(idToken, { clientId, nonce }) {
  const { payload } = await jwtVerify(idToken, JWKS, {
    issuer: "https://api.fades.lol",
    audience: clientId,
    algorithms: ["RS256"],
  });

  if (nonce && payload.nonce !== nonce) throw new Error("Nonce mismatch");
  return payload; // { sub, name, preferred_username, email, ... }
}
import jwt  # pip install "pyjwt[crypto]"

jwks = jwt.PyJWKClient("https://api.fades.lol/oauth/jwks")

def verify_id_token(id_token, client_id, nonce=None):
    key = jwks.get_signing_key_from_jwt(id_token).key
    claims = jwt.decode(
        id_token,
        key,
        algorithms=["RS256"],
        audience=client_id,
        issuer="https://api.fades.lol",
    )
    if nonce and claims.get("nonce") != nonce:
        raise ValueError("Nonce mismatch")
    return claims

Error codes

Errors come back as JSON with an error field. Token endpoint errors follow the OAuth 2.0 format. error_description is included only on non-production servers, so always switch on error and the HTTP status.

Token and revoke endpoints

HTTPerrorWhat it means and how to fix it
401invalid_clientClient authentication failed: no client_id, unknown app, or wrong client_secret. Check your credentials and that you aren’t sending a secret for a public app (or omitting it for a confidential one).
400invalid_grantThe code or refresh token can’t be used. See the causes below.
400unsupported_grant_typegrant_type was missing or not authorization_code / refresh_token.
429rate limitedToo many requests. Wait and retry with backoff. See Limits.
500server_errorAn unexpected problem on Fades’s side. The response includes a request_id. Quote it when reporting the issue. Safe to retry a sign-in after a moment.

Common causes of invalid_grant

SituationFix
Code already used, unknown, or from another environmentCodes are single use. Start sign-in again.

Security checklist

  • Keep the secret server-side. Environment variables only. Never in front-end code, mobile apps or git.
  • Always use PKCE with a fresh verifier per sign-in attempt. Never reuse one.
  • Verify state on the callback, and clear it after use.
  • Send a nonce and verify it if you use the ID token.
  • Use sub as the user key, not the email or username, which can change.
  • Check email_verified before trusting an email address for account linking.
  • Store refresh tokens like passwords (encrypted, server-side) and replace them on every refresh.
  • Request only the scopes you need. Users see them on the consent screen.
  • Revoke on sign-out and when deleting an account.
  • Don’t log tokens, codes, verifiers or secrets. Log the request_id instead.
  • Register exact HTTPS redirect URIs. No wildcards. Use localhost only in development.

Troubleshooting

Sign-in lands on an error page at auth.fades.lol

Either the client_id is wrong, or the redirect_uri isn’t an exact match for one registered on the app. Compare them character by character (scheme, host, port, path, trailing slash).

invalid_grant right after a successful redirect

Most often the redirect_uri sent to /token differs from the one sent to /authorize, or the verifier you saved isn’t the one that produced the challenge. It can also mean the code was already used (a double-fired callback in React strict mode is a common cause) or took longer than 60 seconds.

invalid_client

The secret is wrong, or missing for a confidential app. If you rotated or lost it, delete the app and create a new one. Secrets can’t be recovered.

server_error with a request_id

The problem is on the Fades side, not in your request. Try again in a moment. If it persists, report the request_id so it can be found in the server logs.

Browser console shows CORS errors on /token

Call /token from your server or from your own API route (see Next.js). Browser-only apps should use a public app and the browser example.

UserInfo returns only sub

The user granted only openid. Request openid profile email in scope and have them sign in again.
